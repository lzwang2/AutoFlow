# 游戏专用界面设计规范

- 日期：2026-11-14
- 状态：已实现，自动化及布局验证通过；真实游戏验收待完成
- 校验：2026-11-14 已按当前代码与本次需求复核；校验不代表已完成实现验收
- 首个游戏：Last Cloudia
- 对应计划：[Plan.md](Plan.md)

> 后续增量：首版“Last Cloudia 只提供多人游戏一个功能”的限制已由 [周回活动迁移规范](../week-round/Spec.md) 扩展为多功能模块。涉及功能列表、任务选择和规则/线性任务分派时，以该增量规范为准；本文其余共享运行约束继续有效。

## 1. 目标与范围

保留通用脚本编辑能力，增加左侧纵向导航，让用户进入游戏专用面板后无需手动打开脚本即可选择完整功能并运行。首版实现 Last Cloudia 多人游戏流程，为以后增加其他游戏保留视图和任务边界。

已确认方向：通用编辑器与专用界面并存；专用界面预加载完整脚本。Last Cloudia 首版将整个 MultiPlayerGame 脚本作为一个“多人游戏”功能，不暴露任何游戏配置；“在编辑器中打开”生成独立副本，编辑修改暂不自动同步回面板。导航和共享运行行为按本规范实施；2026-11-15 完成首版代码和基础验证，实际游戏场景尚未验收。

首版不包含第三方插件加载、通用 JSON 自动生成界面、多游戏并行运行，也不扩展脚本引擎语法或添加现有技能不支持的玩法。

## 2. 当前工程依据

- 主界面：`AutoFlow.App/Views/MainWindow.xaml`。
- 主视图模型：`AutoFlow.App/ViewModels/MainViewModel.cs` 及其分部文件；当前集中管理编辑、窗口、捕获和运行。
- 源脚本：[MultiPlayerGame.rules.json](../../../RuleTemplates/LastCloudia/Rules/MultiPlayerGame.rules.json)，格式为 `autoflow/rule-script` v2。
- 脚本依次匹配 `LastCloudia.Welcome`、`LastCloudia.NoRoom`，最后无条件调用 `LastCloudia.MultiPlayerCore`。
- 核心技能：`AutoFlow.Core/Skills/LastCloudia/MultiPlayerCore/MultiPlayerCoreSkill.cs`；现有 `is_room_owner` 参数默认 `false`。
- 共享条件、动作及其图片由现有 `RuleTemplates` 体系解析；技能图片继续沿用技能自己的资源体系。

脚本中的 `OuterWidth=750`、`OuterHeight=1040` 表示窗口外框尺寸，不表示客户区尺寸。专用面板复用实测客户区和现有坐标转换逻辑。

实现前的代码基线与改造依据：编辑器的 `ApplyScriptOuterSize` 会调整窗口并改写编辑器尺寸状态；`RunScriptAsync` 在捕获初始化和窗口激活后才设置 `IsRunning`，且规则运行从编辑器模型重建脚本。专用入口不能直接调用这些流程而继承其副作用：须先占用运行槽位，读取完整脚本，并以独立执行上下文传入尺寸、捕获和引用库。现有 `RuleScriptService.Load` 校验版本，不包含本设计所要求的全部格式与资源预检；预检是本次新增工作，已由完整任务加载服务实现。

## 3. 页面布局

左侧为应用级纵向导航，首版两个入口：“脚本编辑器”和“Last Cloudia”。不与编辑器内部的线性脚本、规则、条件和动作片段等标签混用。默认启动进入脚本编辑器。

```text
┌──────────────┬────────────────────────────────────────┐
│ 脚本编辑器   │ 目标窗口 [选择] [刷新]  捕获方式 [选择] │
│ Last Cloudia │ 当前任务 / 运行状态           [停止]   │
│              ├────────────────────────────────────────┤
│              │ Last Cloudia                           │
│              │ 多人游戏                               │
│              │ 自动选房、刷新、准备、战斗及结算       │
│              │                                        │
│              │ [开始] [停止]                          │
│              │ [在编辑器中打开]                       │
│              │ 无需配置，按预置脚本执行               │
│              │ 脚本加载状态 / 运行日志                 │
└──────────────┴────────────────────────────────────────┘
```

目标窗口、捕获会话、运行状态和停止入口属于应用共享区域。编辑器的新建、打开、保存、另存为只在编辑器页面显示；专用页面只提供完整功能的启动、停止和在编辑器中打开入口，不提供游戏配置或脚本保存操作。目标窗口选择及捕获方式属于共享执行环境，不作为多人游戏的配置项。

窗口不足时，专用面板内容可滚动；开始、停止及错误信息应易于找到，不依赖颜色单独表达运行状态。

## 4. Last Cloudia 功能映射

首版只提供一个“多人游戏”功能，对应完整的 `MultiPlayerGame.rules.json`。自动选房、无房时刷新、准备、战斗、结算及技能已有的异常处理属于功能内部流程，不拆成独立功能或可选开关。

面板仅展示功能名称、简要说明、加载和运行状态，以及开始、停止、“在编辑器中打开”入口。不暴露房主／参与者、规则启用开关、等待时间、次数、窗口尺寸或运行前调整选项，也不创建专用用户配置文件。

运行时完整保留预置脚本的规则、顺序、启用状态与技能参数，包括现有 `is_room_owner=false`。按脚本的 `OuterWidth`、`OuterHeight` 自动调整用户选中的目标窗口并测量客户区；尺寸仅作为内部执行依据，不要求用户填写。窗口调整失败或测量无效时，阻止执行并报告原因。

后续其他完整脚本可以作为新的功能入口加入；本次不实现这些功能，也不提前增加参数配置界面。

## 5. 预加载与资源发布

首次进入 Last Cloudia 页面时自动读取预置脚本并显示加载结果，不自动开始运行。返回该页复用已加载状态；加载失败提供明确错误和“重新加载”。重新加载重新读取完整预置脚本，运行期间禁用。

源文件统一存放在 `RuleTemplates/LastCloudia/Rules/MultiPlayerGame.rules.json`，复用现有模板库目录布局和构建复制规则。专用面板通过 `TemplatePathResolver.TemplateRoot` 和 `TemplateLayout` 加载应用目录下的同名模板；模板浏览器索引同一文件，不再使用 `GameProfiles` 或回退到 `TestScripts`，不依赖开发机绝对路径，不维护第二份手工同步的源脚本。发布包必须同时包含该脚本所需的共享条件、动作、图片及技能资源。

运行时基于应用目录定位资源，不依赖工作目录、仓库目录或开发者绝对路径。复用现有引用和图片路径解析；如果解析依赖引用文件目录，打包时保持该语义。启动前检查脚本格式、引用、图片、技能注册和目标窗口，缺失时阻止运行并报告资源或字段位置。

预加载仅解析数据和检查资源，不调整或激活窗口、不开始捕获、不覆盖编辑器当前游戏、文档、尺寸或窗口配置。Last Cloudia 所需的条件和动作库按该游戏加载，不依赖编辑器当前选中的游戏。校验至少覆盖 Schema、FormatVersion、非空规则、合法外框尺寸、实际使用的条件与动作引用、对应图片，以及核心技能所需的 Common / MultiPlayerCore 图片；技能图片不在脚本引用中，也须显式检查。无关游戏资源的错误不应阻断本任务。

界面区分“脚本已加载”和“可以开始”：未选择有效目标窗口时可完成预加载，但不能运行。开始前重新检查目标窗口及必要资源，再调整窗口、启动或复用匹配该窗口和捕获方式的捕获会话；捕获初始化失败时不进入执行循环。不能仅凭已有捕获对象就复用另一窗口的会话。

功能入口通过预置脚本路径绑定完整脚本，不按规则名称或下标改写规则，也不对技能参数进行面板映射。脚本内部引用继续由现有解析器校验。

## 6. 状态与执行约束

1. 应用同一时刻只有一个运行任务，编辑器与专用面板共享运行协调器和停止能力。
2. 切换页面不停止任务、不重置页面状态、不重新创建执行会话；共享区域显示任务所属页面及运行状态。新一轮任务开始时重置技能的跨轮计数，单次任务内继续保留跨帧状态。
3. 执行状态为待机、启动中、运行中、停止中；启动即占用运行槽位，直到结束、取消或失败清理完成才释放。
4. 运行开始时对完整脚本生成独立快照；执行期间禁用再次开始。首版通用编辑区域暂时只读，左侧导航仍可切换；停止后恢复编辑。脚本及共享引用快照独立于编辑器对象。
5. 运行结束或失败后恢复可操作状态并显示结果。停止调用已有取消机制，不重复另起执行循环。
6. F10 始终停止当前任务；F9 在当前页面发起其任务，已有任务时拒绝重复启动。其他快捷键与停止响应能力不得退化。
7. 切页和预加载不主动切换目标窗口；按既有运行逻辑在开始时调整并激活用户选中的窗口。仅按标题提供候选，不自动开始游戏操作。
8. 从启动中到停止清理结束，固定目标窗口、捕获方式和坐标转换上下文，禁用修改这些运行环境的控件及手动停止捕获入口。F10 在启动中也可取消；任意等待之后须检查取消状态，不能在取消后继续启动解释器。
9. 引用条件和动作的数据也须与编辑器中的可变对象隔离。运行期间在编辑器切换游戏或修改条件、动作、尺寸，不得影响当前任务或替换其引用库；可能改写共享执行环境的操作须禁用或与执行上下文隔离。
10. 停止任务不等同于停止共享预览捕获；正常停止后允许保留捕获供预览。失败时释放此次启动产生的无效会话；关闭应用时取消任务并清理捕获和热键资源。

专用面板开始时，将实测客户区尺寸写入本次执行的坐标转换参考空间，不沿用编辑器上次的参考分辨率。不得通过修改编辑器绑定属性间接保存专用面板的窗口设置；编辑器既有的尺寸和调整偏好仍按原逻辑保留。

## 7. 预置脚本和编辑器衔接

预置脚本作为只读基线，专用面板无需配置，不新增游戏配置读写及自动保存逻辑。执行和交给编辑器时均使用独立内存副本，不写回 `TestScripts` 或应用目录中的预置脚本。

“在编辑器中打开”将当前预加载的完整脚本副本交给通用编辑器，并切换页面。首版没有面板配置需要应用到副本，因此保留预置脚本的所有规则和参数。若编辑器存在未保存修改，应提供保存、放弃、取消选择；取消不替换文档。该副本无默认保存路径，首次保存必须选择位置。编辑器中的修改不自动回写专用面板；首版不支持导入任意自定义脚本作为专用基线。运行期间禁用此入口，普通切页仍然可用。

首版对已有脚本内容采用保守保护：即使尚未实现精细的脏标记，也先提示保存、放弃或取消，避免无提示覆盖。选择“保存”后，仅在保存成功时继续替换；取消保存对话框或保存失败时保留原文档和当前页面。未保存修改检查覆盖会被替换的线性／规则文档；若切换到 Last Cloudia 条件及动作库会丢弃未保存的库编辑，也须先保存、放弃或取消。副本导入后切换到规则编辑和 Last Cloudia 引用环境，保留全部可序列化字段（含 `IdleTickMs`、元数据和外框尺寸）。独立保存及重新打开后的引用仍从应用模板根解析，不依赖副本的保存目录。

## 8. 模块边界

- 应用外壳管理导航，保留通用编辑器内部功能和状态。
- 每个游戏拥有专用 View / ViewModel 和完整脚本任务入口。首版不增加参数适配及游戏配置层。
- 公共运行协调器集中管理目标窗口、捕获、执行和取消；页面不得各自维护互不知情的运行任务。
- 脚本读取、引用解析、规则解释器、技能注册与坐标转换继续复用现有能力。
- 新增游戏时增加对应页面、任务和资源入口，公共执行层不包含游戏专属参数判断。

具体类型名在实施时确定，不为首版引入动态插件系统。

## 9. 验收标准

| 编号 | 验收内容 |
|---|---|
| AC-01 | 左侧导航可切换编辑器与 Last Cloudia，现有编辑及保存功能可用 |
| AC-02 | 首次进入自动加载预置脚本，切页保留页面状态，不自动开始执行 |
| AC-03 | 多人游戏作为单一完整功能呈现，不暴露配置；执行快照完整保留源脚本的规则顺序、启用状态和技能参数 |
| AC-04 | 任一页面运行时均无法启动第二个任务；切页后原任务继续，停止按钮和 F10 可停止 |
| AC-05 | 在编辑器中打开副本不丢失原文档的未保存修改，首次保存需选择位置，不修改预置文件 |
| AC-06 | 在编辑器中打开的副本与运行快照、预置脚本互相隔离；编辑后返回面板仍使用预置脚本 |
| AC-07 | 从仓库外启动构建和发布产物仍可加载脚本、条件和图片，不依赖开发路径 |
| AC-08 | 缺失资源、脚本无效、窗口失效时阻止开始并说明原因；失败清理后可重试 |
| AC-09 | 不暴露窗口尺寸配置，自动按脚本外框尺寸调整并实测客户区，执行与现有脚本行为一致 |
| AC-10 | 预加载不调整窗口或改动编辑器状态；编辑器选中其他游戏时仍能加载并运行 Last Cloudia |
| AC-11 | 启动中可取消且不会稍后开始执行；运行期间不能更换窗口、捕获方式或停止其捕获会话；应用关闭可清理资源 |
| AC-12 | 保存取消或失败不替换原文档；导出的副本保留完整字段，保存到其他目录后可重新加载并解析引用 |
| AC-13 | 专用任务不继承或覆盖编辑器尺寸偏好；编辑器的条件、动作及游戏切换不改变运行中任务的引用和坐标上下文 |

首版已通过 Release 构建、自动化测试与 WPF 布局渲染检查。真实游戏操作验收仍需要 Last Cloudia 窗口及相应场景，不能以基础验证替代。逐项证据见[首版验证记录](../../testing/GameWorkspaces_Validation.md)。

## 10. 运行日志降噪（2026-11-15）

规则循环默认只在首次命中或命中规则变化时记录命中日志；经历无匹配后再次命中也记录。每次运行独立计数，不影响规则执行频率。技能实际事件、异常和启停日志保留。

“调试设置”提供默认关闭的“详细运行日志”，与帧捕获调试分开；启用后恢复每轮规则命中以及技能调用前后日志。该选项在开始时写入执行上下文，对通用编辑器和游戏专用入口都生效，不属于多人游戏参数。
